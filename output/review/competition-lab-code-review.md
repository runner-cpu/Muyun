## 算法与结果口径

- 默认取向仍为 `balanced`，45F + 20E + 20H + 15V 权重与原先从左至右的算术顺序保留。已有四个均衡黄金案例覆盖开局、越冬、缺草和零行动情形，行动序列、分数、展开量与资产保持兼容。
- 三种取向均通过同一生产 `applyAction`、共享拒绝规则及确定性结算评估；先足草且结算现金大于零，再按本取向得分排序。保留至少试算起点一半羊单位、草场每周单次使用、有限候选与提前停止均生效。
- 输出分别披露 F/E/H/V 的值、权重和贡献。E 为 `1−平均退化`，并未伪称最终生态分；H/V 采用当前试算起点基准。没有将不同权重的总分当成可横向比较的评价，也未把有限搜索称为全局最优或完整帕累托前沿。
- 不行动基线和各行动前缀各自独立结算一次；前缀结算结果不流入下一前缀。即时售畜收入、行动费用与结算维护费分别记录，没有重复扣费或重复生长。

## 可复算输入与验证边界

- 当前输入排除真实历史、事件轨迹及递归 tracking；当周只存在于 pending 的草场利用先通过 `pastureUse` 物化为 `grazing/harvested`，休牧计数归零，再执行搜索。不会把已利用小区重新当作可用地，也不会得到额外恢复收益。
- 导出保留版本、公开权重、搜索约束、输入、基线、三取向和逐步结果。FNV 标记明确仅用于意外过期检查，不是身份认证签名；复算通过证明给定输入与当前版本的结果一致，不证明输入来自真实玩家历史。
- 验证器先限制 JSON 字符数、树深、节点数、集合和文本长度，拒绝非有限数与特殊原型字段，再检查严格输入字段、数量及数值范围。公式/约束不一致会在重新搜索前拒绝。
- 验证器重新计算全部输出，仅排除经非负有限数验证的每方案 `elapsedMs`；基线、指标、动作、逐步效果、得分分量、展开量和相同行动引用均参与精确规范化比较，额外未验证字段不能混入。
- 命令行在读取前检查文件大小，错误通过退出码和可读消息返回。单次搜索受宽度 24、深度 5、候选 14 的既定上限约束。

## 高原手记

- 需草使用共享 `feedRequirementKg`，只计存活在栏动物；扣除已放牧后再计算需干草量和缺口，避免负需求。
- 暴雪参数直接调用 `snowRisk(week)`，明确库存不会改变抽签概率。
- 休牧收益先使用共享 `pastureUse` 排除放牧/割草小区，再调用实际 `rest`。冬夏比较使用同一批未利用地，各区退化下降的百分点明确标为合计。
- 羊单位来自共享折算函数，体重饲草负担来自需草函数，两者的用途没有混用。空栏时储草等量周数为 null，未产生 Infinity 或虚构储备能力。
