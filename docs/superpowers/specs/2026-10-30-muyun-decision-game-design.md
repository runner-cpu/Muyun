# 《牧云》玩法重构设计草案

日期：2026-10-30
状态：2026-10-30 用户确认“决策训练与策略实验”路线；本文件记录设计，实现状态见实施计划。
视觉约束：保留现有像素牧场、人物与动物美术，沿用深绿、灰绿与暖土色界面。

## 1. 产品定位与成功标准

推荐定位：**以草畜平衡为主题的牧场决策游戏，提供可复现的策略实验。**

玩家在行动点、现金、草料与草场恢复之间做取舍。科技通过增加可解释的信息帮助决策；结算同时解释经营、生态和动物健康。比赛展示以一次完整的“看见风险—比较方案—执行—复盘”证明作品贡献。

保留十三周完整经营；新增四周固定越冬挑战，让首次体验和答辩能够快速进入核心矛盾。学习目标是理解轮牧、储草和合理减载的权衡，尚不声称经过教学效果验证。

可选路线及代价：

| 路线 | 主要交付 | 取舍 |
|---|---|---|
| 决策训练与策略实验（推荐） | 四季目标、信息科技、三维结算、短挑战、受约束搜索与基线对照 | 改动较多，但形成一套可运行、可解释的闭环 |
| 游戏体验优先 | 任务、事件、成长、短挑战 | 更集中于游戏完成度；不以算法核心作品宣传 |
| 仅针对计算机设计大赛 | 算法实验与资源配置为主，游戏承担交互 | 需要更大幅度调整产品重心；仍须核对目标届次规则 |

推荐路线的验收：

1. 每项科技都有可展示的信息或风险收益，每个雇工都有明确行动收益和持续代价。
2. 高现金不能绕过生态与畜群持续经营要求；卖空不能取得最高综合成果。
3. 固定挑战恰好四次周结算结束；重开获得相同初始状态。
4. 策略算法遵守真实行动点与现金限制，输出实际可执行步骤及评价依据。
5. 方案比较不修改玩家存档；行动轨迹、周轨迹和导出记录与实际操作一致。
6. 旧存档保留经营进度，缺少的历史明确标为缺失。

## 2. 现状诊断

当前循环是查看资源、花三个行动点、周结算、随机事件、下一周。场景和基础模拟已可运行，缺少的是决策价值与结果证据。

| 问题 | 原因 | 改造 |
|---|---|---|
| 项圈、监测没有额外作用 | 只扣费并登记状态，基础信息已经免费公开 | 保留基础信息，新增趋势、风险关注和轮牧试算 |
| 雇工只增加支出 | labor 增加但周行动固定为三点 | 增加下周行动上限，限制最多两个额外行动 |
| 结局偏重现金 | 未计畜群估值、体况和持续经营 | 三维成果与净资产，最高结局附存栏要求 |
| 配种反馈弱 | 局末统一产仔，结果未解释贡献 | 显示妊娠、产仔和资产变化，说明压缩妊娠假设 |
| 事件承诺失真 | 长期收益未实现；部分交易未减少畜群 | 逐项核对文案与效果，交易必须真实记账 |
| 结果难以答辩 | 只展示近期日志 | 周指标轨迹、关键选择、固定挑战与策略对照 |
| 模拟有确定错误 | 离栏孕母仍产仔；暴雪逐头重置随机数 | 修复并加入回归测试 |

## 4. 四季使命与经营结果

使命在季末周结算后记录，不能通过按钮直接领取完成。过程中展示当前值、目标和剩余周次。

| 季节 | 教学与决策目标 | 可验证条件 |
|---|---|---|
| 春 1–3 周 | 建立轮牧习惯 | 本季使用至少两个不同放牧小区，平均退化不高于 0.30 |
| 夏 4–6 周 | 给草场恢复时间 | 季末至少一个小区连续休牧两周，平均退化不高于 0.40 |
| 秋 7–9 周 | 准备越冬储备 | 季末剩余干草可覆盖当前畜群两周需草，现金能覆盖下一周维护 |
| 冬 10–13 周 | 保住健康与经营连续性 | 平均 BCS 至少 2.5，存活羊单位至少为开局的一半，现金大于零 |

阈值是本游戏的关卡设计参数；在模拟基准验证后可调整，但不能写成农牧行业标准。短挑战只评价冬季使命；旧档缺少已过季历史时显示“未记录”。

结算单独展示三项设计评分（0–100）及其原始指标：

- **经营**：以固定冬季价格估值，净资产 = 现金 + 存活畜群估值 + 干草估值。评分按结束净资产 / 有记录的初始净资产计算，基准持平对应 50 分、增长 20% 对应 100 分、减少 20% 对应 0 分，区间外截断。
- **生态**：70% 来自 1 − 平均退化，30% 来自现存草量 / 有记录的初始草量，均截断在 0–1。结果同时展示草量与退化，避免单一数值掩盖透支。
- **动物健康**：40% 来自存活个体平均 BCS 的维护水平（BCS 1→0，BCS 3→1，超过 3 不额外奖励），30% 来自 `health === 'healthy'` 的存活个体比例，30% 来自有记录的存活率。销售与死亡分别记录；空栏时本项为零。

综合成果使用三项等权平均，但最高结局还要求：经营≥40、生态≥60、健康≥70、存栏羊单位至少为初始一半、现金大于零。生态退化≥0.70 或现金为零仍分别触发生态失衡或资金耗尽结局。保留既有 Ending 键以兼容存档，显示文案改为能由数据支撑的经营成果，不凭得分宣称担任合作社职务。

旧存档没有可靠初始基准时，展示当前净资产和原始状态，不伪造增长评分；可持续经营基线从迁移后的首次记录起算，并明确标为“本次续玩起点”。

## 5. 科技与劳动的真实作用

### 草场监测

开通后，对各小区提供两条共享真实公式的试算：现在放牧的采食量、剩余草量和退化变化；保持休牧的下周草量和恢复变化。标出低透支的可行轮牧选择和饲草缺口，不隐藏已有基础数据。

试算明确“按当前状态、未计未来随机事件”。不能直接调用当前 seed 的未来天气或疫病结果作为预测。预测函数为纯函数，不能改变草量、行动或存档。

### 智慧项圈

为真实佩戴个体展示本周 BCS 与上次记录差值、偏瘦/患病关注项和可追溯原因；只对已佩戴动物提供趋势。刚佩戴或旧档没有前次记录时显示“首次记录”，不制造历史。数据来自模拟状态，称为虚拟监测，不宣传真实定位、传感器或疾病诊断。

按实际存活佩戴动物计算可佩戴数量与维护费，销售、死亡后同步；不能因累计登记数阻止为新生个体佩戴。

### 雇工

基础劳动配置为两人，每周三点。新增一名帮工从下一周增加一点，最多五点；雇佣费 3000 元，按现有规则每人每周 260 元。达到上限时禁用并说明。当前周不返还行动，避免循环雇佣获取即时行动。

统一由纯函数计算行动上限，HUD、存档清洗、周流程、指南和前置校验引用同一规则。事件造成的人员变化与行动上限文案也必须一致。

## 6. 四周越冬挑战

- 场景 ID：`winter-challenge-v1`；固定 seed：20261030。
- 起点为第 10 周，终点为第 13 周，按正常规则结算四次；不提前跑完前三季，也不伪造春夏秋历史。
- 初始畜群按完整局的 0.6 倍建立（12 头牦牛、18 只羊），现金 6000 元、干草 2200 kg；四区草量分别为 700、560、420、320 kg/ha，退化分别为 0.10、0.18、0.25、0.32。
- 初始开启草场监测，为十头动物佩戴项圈；6000 元为设备安装后的可用现金，不再收购置费，在第 10、11、12、13 周结算各收一次维护费用。动物佩戴标记与 tech 登记数同步，全部预设完成后建立基线；入口列明这些给定条件。
- 挑战目标为冬季使命及三维成果；只显示有记录的数据，首次项圈趋势须等待周结算。
- 标题页清晰区分完整经营与越冬挑战。挑战使用独立存档键，退出或重开挑战保留完整局存档。
- 结果可同种子重试；新 seed 完整局继续保留。演示时长以实测为准，不先承诺几分钟必然完成。

## 7. 策略算法与对照实验

### 玩家侧：本周受约束策略搜索

实际实现有限宽度 beam search：输入当前可见状态、可用行动点与现金，枚举合法动作序列，保留目标函数较高的有限个候选。默认宽度 24，深度不超过当前行动点（最多五层），候选动作最多 14 个；显示搜索节点数、耗时和实际得到的序列。

候选在每个搜索节点重新生成，包括四区放牧/割草（最多八项）、按当前缺口生成的三个购草档位、治疗、免疫和一项小规模减载（最多十四项），非法或重复候选移除；同一小区在一个计划内合计最多执行一次放牧或割草。买草按实际资金过滤，出售按明确动物 ID 和保留存栏要求过滤。支持提前停止，不强制用光行动。

候选动作经同一引擎校验与执行；拒绝的动作不入队。先将能覆盖本周饲草且结算后现金大于零的方案排在前面；组内使用 `45F + 20E + 20H + 15V`：F 为饲草覆盖率（截断至 1），E 为 1 − 平均退化，H 为动物健康评分 / 100，V 为经营评分 / 100。H、V 按本次试算起点做基准，以与局末相同的公开公式计算。搜索强制保留当前存栏羊单位至少一半；该限制与局末相对开局的持续经营条件分别说明。若无安全方案，返回最高评分的可行方案并指出缺口。搜索不是最优性证明，结果称为“参考方案”。

评分预演只运行可见的确定性阶段，复用真实营养、生长、休牧和成本公式，排除未知天气、事件和疫病抽样。不通过读取 seed 预知未来，不在默认界面承诺真实下周结果。玩家选择后自行执行，试算本身不花行动、不保存到经营状态。

### 完局后：同种子策略对照

完整比较玩家、固定贪心基线和每周重新搜索的策略：从同一场景初始状态、相同 seed 开始；自动策略统一采用相同且可负担的事件选项规则。完整十三周局与四周挑战均在完局后才展示对照，避免泄漏未来事件；旧档只比较真实记录的续玩区间，界面标出起止周次。

搜索策略也必须负担监测：未开通时先合法购买（花现金和一个行动点），余下行动再搜索；买不起则执行相同贪心基线并注明。固定挑战已经包含设备，三方从相同给定配置开始。完整局对比因此同时展示搜索策略的设备购置与维护支出，不能忽略技术成本。

贪心基线固定为优先治疗、放牧最丰草区、缺草时优先补草、其余行动按固定顺序割草，遵守真实约束。所有跳过或拒绝动作有原因。报告明确：同 seed 可复现，不表示不同策略的动物损失一定相同；部分风险依赖策略后的状态。

离线基准在至少 30 个预先公开的 seed 上比较两种自动策略，输出三维指标、净资产、存栏、失败率、搜索耗时和节点数。保留失败案例，不承诺搜索在每局或每个维度胜过基线。该实验只验证模拟中的算法表现，不证明真实牧场收益或教学效果。

## 8. 状态、存档与模块边界

纯 sim 内核继续独立于 Phaser 与 DOM。新增模块按职责拆分，避免继续扩大 run.ts：

| 模块 | 职责 |
|---|---|
| `rules.ts` | 统一动作资格、费用与行动上限，供引擎与界面共同使用 |
| `insights.ts` | 草场试算、项圈趋势、可解释风险 |
| `assessment.ts` / `objectives.ts` | 原始指标、三维结果、季末使命 |
| `scenarios.ts` | 固定挑战与初始条件 |
| `history.ts` | 精简行动与周指标轨迹，不保存递归 RunState |
| `planner.ts` / `policies.ts` | 搜索、候选生成、贪心基线与对照 |

新增的 scenario、assessment、history 字段支持缺省。轨迹包含基线与最多十三次周结算指标；每周保留合法执行的行动、事件选择、已知销售与死亡、项圈个体 BCS。记录结算所属周，不把新周编号写成上一周结果。

沿用当前界面节奏：第 N 周结算只提交一次第 N 周记录（第十三周先计入产仔）；推进到 N+1 周后出现的事件属于 N+1 周，选择纳入下一条周记录。新局和挑战的第一个可玩周不额外抽开场事件，自动策略使用相同顺序。未决事件及本周尚未结算的动作保存为当前周记录草稿，读档继续处理，不重复周结算，也不把新周事件追写为上周结果。

快照至少包含：所属周、现金、干草、固定价格畜群估值、存栏数和羊单位、平均 BCS、健康数、草量、平均退化、自记录起点后的死亡数与出生数。基准另存来源（开局或续玩起点）。存活率的分母为基准存栏数加记录内出生数；未知旧死亡不计入新记录，也不声明整个旧局的存活率。

Animal 增加可选退出原因与周次，区分销售、死亡；旧档未知原因保持未知。新增基准从可验证的起点记录，不能回推或补造旧轨迹。除指标基线外，另保存一次 replayOrigin，包含重放所需的实际起点状态（动物、草场、资源、科技、当前周草稿与事件状态等），排除 history、assessment 和嵌套 origin，避免递归复制。新局同时保存场景配置和模拟版本；旧档只能以实际续玩起点重放。导出 JSON 包含 schema、模拟版本、场景配置、seed、replayOrigin、行动、周轨迹、评价公式版本与来源说明。

保持现有 schema v2，显式校验新增字段及数组长度；若以后升版本，迁移必须真实保留 v2，避免当前 `version < SAVE_VERSION` 路径重置整个旧局。挑战与完整经营独立存储，错误提示不能声称已保存成功。

## 9. 规则一致性与确定错误

1. 只允许存活孕母局末产仔，已售/死亡母畜不能产仔或转为泌乳。
2. 暴雪受害者选择在遍历前创建一个 RNG，每个候选推进该 RNG；保持同 seed 可重放。
3. 疫苗、监测重复购买在引擎层同样拒绝；项圈按真实存活佩戴数计算。
4. 事件支付前校验现金与资源，不允许把不足资金截断为零后获得完整服务；防止重复解析同一事件。复制 flags 等将被修改的嵌套字段，确保引擎转换不改变源状态，拒绝操作不消耗行动。
5. “收购商”等出栏事件须实际移出指定存栏，并记录销售原因；纯现金奖励不得伪装成畜群交易。
6. 打井、合作社等尚未实现的长期机制，改成诚实的即时效果描述；本轮不添加新的大型长期系统。
