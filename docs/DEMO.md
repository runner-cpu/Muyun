# 《牧云》演示与操作指南

更新日期：2026-10-30，当前模拟规则 `decision-v2`，规划器 `beam-profile-v2`。下面按五分钟左右编排，属于排练目标，没有把该时长当作已测结果。演示需真实完成四次周结算；机器速度、阅读与操作熟练度会影响用时，正式录制前应完整排练并记录实际时长。旧模拟 v1 和旧规划器报告保留为历史，不套用为当前操作结果。

## 演示前准备

在 `client` 运行 `npm install`、`npm run dev`，打开本地网页；正式展示也可使用通过构建的静态版本。桌面用键盘鼠标，手机建议横屏。保留浏览器下载权限，避免演示过程中清除本地存储。

标题的「开始新的一局 / 继续存档」属于十三周完整经营；「越冬挑战 · 四周 / 继续挑战」属于独立挑战。若已有完整局，进入或重开挑战会保留它。开始新的挑战会替换原挑战进度；要接着原进度演示，应选择「继续挑战」。

演示先用一句话说明目标：**在高原的季节窗口中，用有限行动与资金安排冬草、休牧和畜群，比较不同偏好的实际后果。** 画面保留像素牧场，经营数值来自同一模拟状态。

## 四次周结算的完整操作

每周先看概览、储备账与试算，再亲自执行。三周账固定当前畜群和体重，只有当周放牧抵当周，未来不新增草源；账中草费是假设补足的参照，不自动买草、不保证行动点足够，也不预知天气。查看距季末/局末的次数和固定开局基线保留目标，再决定本周如何取舍。

四个经营入口可直接点击，也可用 `1` 畜群、`2` 草场、`3` 集市、`4` 科技打开；`Esc` 关闭允许关闭的面板。不要为展示用完行动点，安全的空序列可以直接结算。每区每周只能放牧或割草一次；两者都会中断连续休牧，已使用区本周不能获得自然恢复，草场安排显示的利用状态应与按钮和地图一致。

1. **第 10 周：把信息变成一次真实行动。** 在三周账查看库存缺口、假设补草费和维护，并核对全局存栏底线；按需用高原手记解释需草和连续休牧关系。进入试算运行三种偏好对照，先比较共同基线与原始指标，再选择一个参考方案，记下小区、购草量、个体耳标和动作顺序。核对方案的全局保留余量，展开一步查看「行动后即刻」与「若此时结算」的现金和干草，导出本周实验单。关闭试算，按序打开对应经营面板：在指定小区点「安排放牧」或「收割干草」；购草在集市「自定义购草（整公斤）」输入建议量、核对费用，再点「按数量买草」；减载按耳标筛选/翻页找到个体后出售；治疗在畜群面板操作。每次看行动点、现金、草量或存栏的实际变化，再返回概览核对缺口与资金风险。点「结束本周」，核对确认面板后确认，阅读周回顾。完成第 1 次结算。
2. **第 11 周：检查随机后果再决定。** 若出现事件，阅读即时效果、费用和不可用原因，选择可执行的常规选项；资源不足兜底只在常规选项全部非法时出现，并承担 BCS −0.2 与退化 +0.02 的有界损失。查看上一周实际饲草、BCS、退化和现金变化；点击场景牲畜或畜群耳标查看同一真实个体档案，去科技面板查看已佩戴个体的记录趋势。返回概览重新试算，按当前方案手动执行，再结束本周并阅读回顾。完成第 2 次结算。
3. **第 12 周：比较储草与休牧。** 处理新周事件，查看草场安排与预测，并对照地图上的草量密度、裸土、收割茬行和利用标签。指出收割会打断连续休牧，低退化小区和足草条件不一定等于最赚钱方案；根据当前现金、干草与动作预算执行自己的安排，结束本周。完成第 3 次结算。
4. **第 13 周：保留持续经营条件。** 处理事件，核对冬季使命：平均 BCS 至少 2.5、保留起点至少一半羊单位、有存活牲畜、现金为正。再次试算并自行安排，确认最后一次结算。完成第 4 次结算后进入结局。

如果手动动作与原参考方案不同，应按新状态重新试算；不要把旧截图当成当前建议。买不起或没有行动点的操作会显示原因；没有安全方案时，试算也会明确显示风险。不要为了演示成功而口头隐藏损失或跳过记录。

## 结局、对照、导出与重开

结局页先读三维成果和原始指标。经营分基于净资产相对真实记录起点的变化，生态分同时考虑退化与草量，健康分结合 BCS、健康比例和已知存活情况。现金是余额，不是收入。综合分是三维均值；最高成果另要求维持存栏和正现金。

同条件对照要分别看引擎是否完成、最高成果是否达标和保留存栏条件。完成只表示正常走完引擎，不代表没有资金/生态失败；未触发失败也可能只是「维持经营」。以本次真实玩家结果为准，不为演示把未达标讲成高成果。

展开逐周记录，应能看到第 10、11、12、13 周各一条，以及本周行动和事件选择。点击「运行同条件对照」，三方从同一挑战配置与 seed 开始，两自动策略采用同一可支付事件规则。此处搜索每周使用默认均衡偏好，并非三种本周偏好的完局排名。搜索在完整局中需要实际购置监测；挑战已经预装，维护照常扣除。不同策略改变风险状态，损失不必相同。

点击「导出本局 JSON」，当前挑战文件名为 `muyun-winter-challenge-v1-20261030.json`。页面提示只是已发起下载，应检查浏览器是否实际保存文件。JSON 应含 `schema`、模拟/评价版本、场景配置、seed、`replayOrigin`、基线、四周记录与最终结果。技术回放可验证指标，界面暂不提供 JSON 导入。

下载完成后，点「重新挑战相同条件」回到固定第 10 周配置，说明可以比较另一种选择。若需展示隔离，可在重开前先点击结局页的「返回主菜单」，检查完整经营仍可「继续存档」，再选「继续挑战」返回已结束挑战的结局并重开。完整局键 `muyun-save` 与挑战键 `muyun-save-winter` 分开保存。不要用「清除浏览器数据」代替重开。

## 技术答辩：复算本周实验单

这段可独立于五分钟主演示安排，先排练实际所需时间。试算页下载第 10 周实验单时，文件名为 `muyun-week-20261030-w10.json`，schema 为 `muyun-week-experiment-v1`；它包含可见当前输入、模拟/规划器版本、三组公开权重和约束、共同基线、动作前缀与预测，不包含真实周轨迹。不要把它展示为已执行的经营结果。

在 `client` 打开终端，替换为实际下载文件路径：

```bash
npm run sim:verify-week -- "C:/Users/runner/Downloads/muyun-week-20261030-w10.json"
```

核对输出 `valid: true` 与复算说明。校验器从输入重新计算，除合法的运行耗时外，权重、约束、基线、方案、逐步效果、指标和搜索量都必须一致；通过说明当前版本模型内一致，不认证输入来源，也不导入存档。若文件版本与工程不符，应保留对应版本后复算；若真实状态已变，回到试算页重新运行再导出。

可在备用副本中修改一个输出指标演示拒绝，并保留原文件，避免把失败文件和正式证据混淆。正式材料同时保留周实验单与完局 `muyun-run-v1` 文件，分别说明「假设预测」和「真实记录」。

## 答辩中的证据与边界

可以展示真实搜索参数：每种偏好 beam width 24、最多五层、每节点最多 16 个候选、单组最多扩展 1552 节点，遵守现金、行动点和本次试算保留存栏限制。v2 额外考虑整公斤小缺口，以及维护后保留至少 1 元仍补不齐时的部分补草量，不改模拟价格或得分。均衡/草场/资产偏好分别使用 `45/20/20/15`、`45/35/15/5`、`45/10/15/30` 的 F/E/H/V 权重。不同权重总分不能横向排名；E 只用平均退化，不能当作局末生态分；三种有限参考方案不构成全局帕累托前沿。节点与耗时来自当次计算，不能用固定宣传数字代替。

`decision-v2` / `beam-profile-v2` 基准使用两个场景各 30 个公开 seed。当前完整局搜索失败 0/30、贪心 30/30（28 次资金耗尽、2 次生态失衡）；挑战搜索 0/30、贪心 1/30。但四组最高成果达标均为 0/30，搜索两场景全部为「维持经营」，全局留存条件分别仅 24/30、29/30 达到；挑战搜索平均经营分 19.20 低于贪心 23.25、净资产 94,138.50 元低于 95,964.03 元，健康分同为 98.87。新候选没有提高这批终局分数。引用时同时展示取舍，完整表和失败在 `SIMULATION.md` 及本机报告中；这是模型和脚本的实验，不是最优性或真人难度证明。

如被问到仍存在哪些问题，应说明固定冬价估草与单周目标可能诱导过度储备，季末使命和本周得分尚未完全对齐；饲喂、人手事件等规则口径留待独立版本与专业核对。本轮三周账与全局阈值揭示风险，没有据此宣称真实经济或教学效果已改善。

场景按每种存活牲畜的 45% 向上取整、每种最多 18 头抽样；每个精灵绑定真实在栏 ID，红菱、黄三角和青色颈带分别提示患病、体况/健康关注和项圈。画面样本不是完整畜群，坐标只是展示槽位，不表示该头动物实际所属放牧区或真实移动路线，准确总数以 HUD 与全部畜群表为准。

存档 schema v2 与模拟版本分别编号。继续旧模拟版本存档时保留经营进度和已知当周小区利用，从当前状态重新建立 v2 基线；不要把升级前记录说成 v2 全局轨迹。已经结束且没有可玩起点的旧档不提供策略对照。正式演示应从当前版本新建挑战获得完整四周证据。

高原特色由冬草储备、季节再生、连续休牧和牦牛/藏羊两种负担尺度共同呈现。说明时区分观察到的当前数值、游戏中的因果规则和真实农牧知识；干草等量周数不含未来放牧与变化，冬夏对照只用于同批当前休牧地。评分与使命是游戏设计参数，教育目标尚未经过学习效果研究；项圈和监测读取游戏状态，没有真实 IoT、定位或疾病诊断。素材来源保留在 `ASSETS.md`，赛事资格与下一届要求需另行核对，见 `COMPETITION.md`。
