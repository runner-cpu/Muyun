# 牧云界面梳理与优化

## 改造前诊断

模拟、状态、场景、DOM UI 已分层，但展示层未表达这套结构。四项经营功能只能靠走近触发，资源缺少单位与风险解释，行动结果缺乏可见反馈。畜群只显示前40头，出售仅展示最高价6头。README 停留在早期骨架说明。视觉存在棕色厚框、低对比小字、英文装饰标签和移动端关键数值隐藏问题。

## 方案比较

1. 仅调色与间距：代价小，但无法改善玩法理解和入口可达性。
2. 保留像素场景，重组经营外壳：本轮采用。补齐可达入口、决策预览和反馈，用一致视觉体系串联。
3. 改成完整管理台或更换引擎：会遮盖游戏场景，成本与收益不匹配。

## 已确认方向

用户确认保留像素风。保留原玩法、功能名称与存档版本兼容，补入必要的未决事件标记；界面采用高原晨光、冷杉绿和草金色。利落直角、清晰中文排版，像素字体只用于标题与主要游戏标识。提供浅/深/系统主题，尊重减少动效设置。

## 信息结构

- 标题页：名称、十三周目标、开始/继续、玩法、设置，真实像素风高原图。
- 牧场：顶部周次/天气/资源，底部畜群/草场/集市/科技，侧边简短本周提示与饲草收支；场景保持开放。
- 经营：统一摘要、对象、消耗、反馈；畜群和出售按种类筛选和分页。
- 本周概览：真实需求、已放牧、库存、缺口、风险、近期日志。
- 推进：确认剩余行动点及饲草风险，结算回顾，再处理下周事件。

## 后续分阶段路线

### 第一阶段：让科技提供真实信息

- 为项圈、草场扫描定义并实现玩家可使用的信息输出，再决定是否移除“试验功能”说明。
- 每项技术在购买前说明一次性及持续费用，展示能影响经营决定的真实结果；不只播放成功反馈。
- 明确场景中代表性动物与 sim 个体的关系，避免画面数量被误解为全部存栏。

### 第二阶段：加固存档与状态边界

- 从根字段检查扩展到动物、草场、科技、日志及未决事件等嵌套结构；校验 ID 关系、有限数值、范围与数组内容。
- 记录各版本迁移和旧存档的可恢复边界；损坏存档提供明确提示和安全恢复路径。
- 围绕真实损坏与迁移案例验证，而不是仅复刻当前存档结构。

### 第三阶段：真机性能与经营平衡

- 在目标手机横屏上实测首屏加载、字体和美术加载、场景帧率、触屏遮挡及长列表操作，再按结果设定预算和拆包方案。
- 以确定种子和批量仿真分析不同放牧、补草、繁殖、交易策略的收益与风险；检查十三周节奏和五种结局的可达性。
- 邀请首次玩家走完整局，验证理解行动点、饲草缺口和科技价值所需的帮助，再调整难度和引导。
