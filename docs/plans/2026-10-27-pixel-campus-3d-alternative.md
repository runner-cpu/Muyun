# 像素校园交互地图 · 详细方案

> 目标形态：浏览器里可"游玩"的像素风 3D 校园地图。等距视角、角色漫游、昼夜循环，校园每个区域都是一个可交互的小游戏点。
> 默认假设：单人开发、周期约 8 周、Web 端交付（可部署 GitHub Pages / Vercel）。如与实际不符，排期按比例调整。

---

## 1. 技术路线（核心决策）

**主路线：Blender 建模 → glTF 导出 → Three.js 实时渲染 + 像素化后处理**

- Blender 只承担建模/UV/动画/导出（DCC 角色），不做引擎。
- 为什么选实时 3D 而不是渲染成 2D 图集拼地图：只有实时 3D 才能低成本实现角色漫游、昼夜循环、点击交互和相机缩放，且 Blender 资产直通 glTF，管线最短。
- 像素化实现（"像素味"的命门，Phase 0 必须最先验证）：
  1. 场景渲染到低分辨率 RenderTarget（逻辑高度固定 216px，宽随屏幕比例），`NearestFilter` 放大 → 得到硬边像素。
  2. 色板量化：片元着色器把颜色吸附到全局调色板（简化版每通道 8 级，进阶版用 32 色 3D LUT）。
  3. 相机用正交（Orthographic）等距视角，滚轮缩放只改 ortho zoom，不破坏像素栅格。
- 交互框架：原生 Three.js + 自写轻量状态机；对话/弹窗 UI 用 HTML/CSS 叠加层（开发快、中文排版好处理）。
- 备选路线：Godot 4 导入 glTF 做 Web 导出。交互开发更快，但 Web 包体大、加载慢、定制像素管线不如 Three.js 可控。默认不选。

## 2. 美术规范（像素感的纪律，全项目强制）

- **色板 ≤ 32 色**，分组：天空 4 / 建筑 10 / 地面 6 / 点缀 8 / UI 4。起步可参考 PICO-8 的 16 色再按校园实景照片调：
  `#000000 #1D2B53 #7E2553 #008751 #AB5236 #5F574F #C2C3C7 #FFF1E8 #FF004D #FFA300 #FFEC27 #00E436 #29ADFF #83769C #FF77A8 #FFCCAA`
  Blender 里建一个只含色板材质的 `.blend` 资产库，所有模型只允许从库里拖材质——统一感的来源。
- **建模**：全部低多边形 + 硬边着色（Shade Flat）。建筑 = 盒子 + Geometry Nodes 窗户阵列；树做 2~3 种预制（球冠/锥冠/圆柱干）散布复用。
- **比例卡**：1 unit = 1 米，人物 1.6，门 2，层高 3.6。建一个参照场景，新模型先过比例卡。
- **灯光**：仅一盏 Directional（太阳）+ 环境色；昼夜 = 太阳角度与颜色 LUT 插值。阴影不用阴影贴图，用 blob shadow 圆片（更"像素游戏"、性能更好）。
- **命名**：`Campus/<区域>/<物体>`（如 `Campus/Library/Bookshelf_A`）。写一个 Blender 校验脚本检查命名与非法材质，导出前跑一遍。
- **导出**：glTF 2.0（+Draco 压缩）；角色动画导出为 clip；导出预设保存为 `.json` 固定下来。

## 3. 场景与交互设计（每个场景 = 一个玩法点）

底层统一为**事件点系统**：场景里放 TriggerZone（进入或点击触发），挂一个玩法配置。加新场景 = 建模 + 配 trigger + 写玩法脚本，三者解耦。

Trigger 配置示例（JSON 驱动，内容可扩充不改代码）：

```json
{
  "id": "library_quiz",
  "zone": "Campus/Library/Triggers/DeskZone",
  "trigger": "click",
  "action": { "type": "minigame", "game": "libraryQuiz", "rewards": { "credit": 2 } }
}
```

### 场景清单

| # | 场景 | 玩法类型 | 产出 |
|---|------|----------|------|
| 1 | 校门广场 | 仪式/叙事 | 签到、成就 |
| 2 | 主教学楼 | 信息/氛围 | 学分 |
| 3 | 图书馆 | 经营+问答 | 学分、心情 |
| 4 | 食堂 | 选择/养成 | 心情 |
| 5 | 宿舍区 | 时间锚点 | 推进昼夜 |
| 6 | 操场/体育馆 | 动作小游戏 | 心情、成就 |
| 7 | 湖心花园 | 收集/休闲 | 图鉴、心情 |
| 8 | 全图彩蛋点 | 探索 | 图鉴、成就 |

**1. 校门广场**：走进校门触发"每日签到"（记录连续天数，第 7 天成就）；保安大爷 NPC 可对话（对话树含校园梗）；公告板显示版本更新和校园通知。
**2. 主教学楼**：点击亮灯窗户 → 弹出该教室当前课程卡片；上课时间进入教室可"听课"得学分；下课铃响时门口播放人流动画。
**3. 图书馆**：座位俯视图（哪些被占、被谁占——NPC 有名字）；书桌点击触发知识问答（校史/高数，答对 +2 学分）；闭馆前 5 分钟全馆灯光变暖 + 音乐彩蛋。
**4. 食堂**：菜单每日轮换（用真实食堂菜单最讨喜）；打饭三选一，不同菜影响心情值；饭点高峰出现排队 NPC 动画。
**5. 宿舍区**：进宿舍"睡觉"= 时间快进到第二天早晨（游戏核心循环的锚点）；阳台晾衣服随机事件；楼下常驻一只可撸的猫（心情 +1，每日一次）。
**6. 操场/体育馆**：跑步节奏小游戏（连打空格/连点屏幕，按节奏得分）；投篮小游戏（蓄力条概率）；夜跑模式（晚上来操场，路灯亮起，氛围分拉满）。
**7. 湖心花园**：钓鱼小游戏（时机条玩法，鱼种图鉴）；投喂锦鲤彩蛋（连续投喂 7 天出金色锦鲤王）；四季切换按钮在此展示。
**8. 全图彩蛋**：校园猫图鉴（全图散布 7~10 只猫，点击收集）；"考试周模式"开关（全图饱和度降低 + 雨天 + 背景音变化，情绪价值传播点）；天文台夜间触发流星雨。

## 4. 全局游戏系统

- **玩家控制**：WASD/方向键 + 点击地面寻路（导航网格或网格化 A*）；碰撞用简化胶囊 + AABB；移动端单指虚拟摇杆、双指缩放。
- **时间系统**：游戏内一天 = 现实 4~6 分钟；昼夜驱动灯光 LUT、NPC 密度、场景玩法开关（食堂只在饭点营业、图书馆 22:00 闭馆）。
- **数值循环**：三条线——学分（上课/问答）、心情（吃饭/休闲/撸猫）、图鉴（探索）。轻量成长感即可，不做复杂 RPG。
- **NPC**：学生流（沿路点循环 + 随机停留）、猫（待机 + 被互动）、剧情 NPC（定点）。走路用 4 帧 sprite 式关键帧或简单骨骼。
- **对话系统**：JSON 对话树 + 打字机文本框：

```json
{
  "npc": "guard_uncle",
  "lines": [
    { "text": "同学，刷卡进门……哦是你啊，来这么早？", "next": 1 },
    { "text": "今天食堂二楼有锅包肉，去晚了可就没了。", "end": true }
  ]
}
```

- **存档**：localStorage（数值、图鉴、签到日期、成就）。
- **成就**：10 个左右（连续签到 7 天、钓到锦鲤王、集齐猫图鉴、考试周全勤……）。

## 5. 制作排期（单人 8 周，每阶段有验收标准）

| 阶段 | 周期 | 内容 | 验收标准 |
|------|------|------|----------|
| Phase 0 管线验证 | 第 1 周 | 1 栋楼 + 地面 + 像素化 shader + 角色走动 + 点击弹窗 | 浏览器 60fps，像素感成立，Blender→Web 全链路打通 |
| Phase 1 地图骨架 | 第 2~3 周 | 全区域 blockout、漫游 + 寻路、Trigger 框架、对话 UI | 可以从校门走到任何一个空场景，trigger 均能触发 |
| Phase 2 场景填充 | 第 4~6 周 | 逐场景完成（每场景 ≈ 建模 1~2 天 + 玩法 1~2 天），优先校门/图书馆/食堂三个门面 | 8 个场景交互全部可玩 |
| Phase 3 系统串联 | 第 7 周 | 昼夜、NPC、数值、存档、成就 | 从签到到睡觉一整天的完整循环可跑 |
| Phase 4 打磨发布 | 第 8 周 | Draw call 合并/Instancing、移动端适配、加载页、宣传长图与 GIF、部署 | 移动端可流畅游玩，总包 < 15MB |

## 6. 性能与发布要点

- Draw call：同材质合并、树用 `InstancedMesh`；目标 Web 端 < 300。
- 资产：glTF + Draco，纹理尽量少（低多边形平面色 + 顶点色为主）；首屏总包 < 15MB。
- 分辨率策略：像素逻辑高度固定（216px）适配各屏幕，避免非整数缩放导致的像素大小不均。
- 部署：GitHub Pages / Vercel；加一个极简访问计数（答辩时"上线 X 天、访问 X 次"是有效数据）。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 范围失控（最常见） | 场景分三级：3 门面 + 3 次要 + 2 彩蛋；时间不够先砍次要场景 |
| 像素感翻车 | Phase 0 用真实色板和最终管线验证，不等做完再调 |
| 建模风格漂移 | 每个模型过"色板库 + 比例卡"双检查；校验脚本自动化 |
| 移动端性能 | 树/NPC 数量做画质开关（低配自动减半） |

## 8. 差异化加分项（比赛答辩讲点）

1. **考试周 / 毕业季一键切换**——情绪价值，传播性强。
2. **猫图鉴 + 全校彩蛋**——二次传播的社交货币。
3. **真实数据接入**：如学校有图书馆座位/课表公开接口，接入后是答辩王炸。
4. **像素合影模式**：生成像素风头像合影卡，可保存分享。
