# 像素校园 Web 游戏 · 完整执行方案

> **执行修订（2026-10-27）**：已按本方案开工，并用青海大学公开地图数据把占位校园替换为相对布局；技术栈保持 Phaser 2D。与 Three.js 3D 备选方案的取舍、素材/音频/UI/存档的偏差见 `docs/DECISIONS.md`。

**项目代号**：Pixel Campus（可改）
**一句话**：打开网页就能游玩的像素校园世界——复刻你的大学，室外核心环线 + 宠物对战 + 躲猫猫，手机电脑都能玩。
**制作方式**：1 人 + AI 辅助开发
**周期**：15 周（含准备周），无硬性截止
**预算**：≈ 0 元
**目标**：个人作品集 + 自己玩；v2 加联机与室内

## 2. 关键决策与理由

### 2.1 技术栈（以"AI 辅助友好"为第一标准）

**Phaser 3 + TypeScript + Vite + Tiled + localStorage；部署 Vercel / GitHub Pages；v2 联机用 Colyseus。**

- 纯文本工程：所有代码、配置、地图数据都是文本，AI 能完整读写和调试——这对"全靠 AI 辅助"是决定性优势。
- Web 原生：打开链接即玩，首屏 < 5MB；Godot Web 导出 20~40MB、启动数秒，且 .tscn 场景高度依赖 GUI，AI 辅助困难。
- Phaser 的 Tilemap、Arcade 物理、像素渲染（`pixelArt` + `roundPixels`）开箱即用。
- 免费：引擎、工具、托管全部 0 成本。

### 2.2 视觉规格

- 俯视 3/4 视角（建筑带立面，可遮挡），8 方向自由移动。
- 16×16 瓦片；逻辑分辨率 480×270（16:9）；整数倍放大 3~4 倍；`roundPixels: true`。
- 单屏约 30×17 瓦片；首版地图约 120×90 瓦片（约 4×5 屏）。

### 2.3 美术路线（不会手绘的解法）

**"素材包拼装 + 调色板统一"，而不是"画"：**

1. 主素材包打底（Kenney CC0；LimeZu free 版，使用前核对授权，非商业作品集通常免费）。
2. 地标建筑用瓦片"拼装"：屋顶 + 墙体 + 窗户 + 门 + 招牌，对着实景照片组合，尺寸和配色对齐真实建筑。
3. 全局 32 色调色板；所有素材（含 AI 生成）必须吸附到同一色板。
4. AI 生成只用于：宣传图、加载页、UI 图标、头像；**不用于瓦片级素材**（一致性不可控）。
5. 角色用免费四方向 spritesheet，调色板换色区分 NPC。

### 2.4 音频

CC0 免费素材（OpenGameArt / freesound / Kenney Audio）为主，AI 生成补充 BGM；记录每首曲子的授权。

## 3. 游戏设计规格（v1）

### 3.1 核心循环

起床（宿舍）→ 逛校园 → 上课（主楼，+学分）→ 吃饭（食堂，+心情）→ 自由活动（撸猫 / 小游戏 / 收集）→ 回宿舍睡觉（推进到第二天）。

### 3.2 地图规格（核心环线）

| 区域 | 内容 | 交互点 |
|---|---|---|
| 校门广场 | 校门、门卫室、公告板 | 每日签到、保安对话、公告 |
| 主教学楼 | 主楼外立面、入口 | 上课（+学分）、课程表 |
| 图书馆 | 图书馆建筑、门前台阶 | 知识问答、座位提示 |
| 食堂 | 食堂建筑、档口窗口 | 打饭三选一（+心情） |
| 宿舍区 | 宿舍楼、阳台、楼下空地 | 睡觉（推进时间）、撸猫 |
| 操场 | 跑道、看台、球场 | 宠物对战入口、躲猫猫入口 |

- 区域之间用道路连接，步行一圈 2~3 分钟。
- 每栋建筑一个 TriggerZone；首版不做室内，点击门显示"敬请期待/后期开放"。

### 3.3 玩家与操作

- 8 方向移动，Arcade 物理碰撞；相机跟随 + lerp + 边界限制。
- 交互：靠近显示"E"提示；键盘 E / 空格，移动端点按目标。
- 移动端：左下虚拟摇杆，右下交互键；横屏为主，竖屏提示旋转。

### 3.4 NPC 与猫

- 5 个剧情 NPC（保安、食堂阿姨、图书管理员、猫协同学、神秘训练师），各带 2~4 句对话与简单日程。
- 5 只校园猫散布全图，点击收集，进"猫图鉴"；其中 3 只可成为宠物对战出战单位。

### 3.5 交互清单（首版 15+）

签到、公告板、保安对话、上课、课程表、图书馆问答、座位提示、打饭、食堂阿姨对话、睡觉、撸猫、猫图鉴、宠物对战、躲猫猫、操场看台、自动售货机（心情+1）、路灯开关（夜景彩蛋）。

### 3.6 小游戏 A：宠物对战

- **入口**：操场"神秘训练师"，需先收集至少 1 只猫。
- **宠物数据**：HP / 攻击 / 速度 / 技能 1 / 技能 2；三系克制（橘→黑→白→橘，伤害 ×1.5）。
- **流程**：选择宠物 → 回合制（玩家选技能 → 结算 → NPC 行动）→ 胜负 → 奖励（学分/心情/图鉴）。
- **公式**：伤害 = 技能基础值 × 属性克制 × (0.85~1.0 随机) − 防御修正。
- **数据驱动**：`pets.json`、`skills.json`，新增宠物不改代码。
- **扩展预留**：联机版改为服务器校验回合，逻辑结构不变。

### 3.7 小游戏 B：躲猫猫

- **入口**：操场 NPC 或公告板触发。
- **规则**：从 6~8 个预设藏点随机选一个藏 NPC；90 秒内找到；距离越近提示越"热"（音效/文字）。
- **失败/成功**：成功 +心情 +成就；失败可重试（每日 3 次）。
- **扩展预留**：联机版改为真人躲藏，服务器判定。

### 3.8 时间、昼夜与存档

- 游戏内一天 = 现实 6 分钟；早晨/白天/黄昏/夜晚四段，用全屏色调叠加实现（避免复杂光照）。
- 部分交互限时（食堂饭点、图书馆闭馆）。
- 存档：localStorage，JSON schema 带 `version` 字段，为未来账号迁移留 `userId` 占位。
- 存档内容：位置、时间、学分、心情、猫图鉴、成就、签到记录、设置。

### 3.9 UI/UX

- 标题页（开始/继续/设置）→ 加载页（进度条+小提示）→ 游戏。
- HUD：时间、学分、心情、当前任务提示。
- 对话框：底部打字机文本 + 头像 + 选项。
- 所有 UI 用 HTML/CSS 叠加层实现，中文排版与适配更省事。

## 4. 技术架构

### 4.1 目录结构

```
client/src/
  scenes/BootScene.ts
  scenes/PreloadScene.ts
  scenes/TitleScene.ts
  scenes/CampusScene.ts
  scenes/UIScene.ts
  scenes/minigames/PetBattleScene.ts
  scenes/minigames/HideSeekScene.ts
  systems/InputManager.ts
  systems/InteractionSystem.ts
  systems/DialogueSystem.ts
  systems/TimeSystem.ts

  data/triggers.json dialogues.json pets.json skills.json hidespots.json
public/assets/{tilesets,sprites,audio,ui}
```

### 4.2 场景流

Boot → Preload（加载资产）→ Title → Campus（世界）+ UIScene（叠加）→ 小游戏 Scene（暂停世界、叠加运行）→ 返回 Campus。

### 4.3 核心接口约定

- `InteractionSystem.trigger(id)`：所有交互唯一入口。
- `DialogueSystem.start(dialogueId)`：Promise 返回选项结果。
- `MiniGame.start(config): Promise<Result>`：小游戏统一契约，主场景发奖励。
- `SaveSystem.save()/load()`：唯一读写存档入口。
- `NetworkAdapter`：v1 空实现，v2 替换为 Colyseus 实现。

### 4.4 性能预算

- 桌面 60fps、中端手机 30fps+；首屏 < 5MB；纹理图集合并；同屏精灵 < 150；地图按区域切块加载。

## 5. AI 辅助开发工作流（本项目成败关键）

### 5.1 工具链

- 编辑器：VS Code；版本控制：Git + GitHub（免费）。
- 开发：ZCode / AI 编程助手（本项目环境即可）。
- 地图：Tiled（免费）；像素修整：Piskel / LibreSprite（免费）；音频剪辑：Audacity。

### 5.2 工作纪律（必须遵守）

1. **一次只做一个功能**，验收通过再下一个；禁止"帮我把整个游戏做出来"式提示。
2. **每个功能一个 Git commit**；AI 改坏了就 `git revert`，不要硬修。
3. **每个功能给验收标准**（能走、能点、能存档），让 AI 自测并修复构建错误。
4. **控制文件规模**：单文件 < 300 行；超了就要求 AI 拆分。
5. **每周更新 `PROJECT.md`**：当前进度、已知问题、下一步；每次开新会话先让 AI 读它。
6. **报错必贴完整控制台信息 + 复现步骤**，不要让 AI 猜。

### 5.3 提示词模板

- 新功能：「在现有 Phaser 项目中实现 X。只修改 A、B 两个文件。验收标准：……。完成后运行 `npm run build` 并修复所有错误。」
- 修 Bug：「现象：……；复现：……；控制台报错：……；相关文件：……。先分析根因，再做最小改动修复。」
- 重构：「保持行为完全不变，把 X 拆分为 Y 和 Z，单文件不超过 300 行，完成后跑构建。」

### 5.4 测试策略

- 核心逻辑（伤害公式、存档序列化、时间推进）用 Vitest 写单元测试，由 AI 生成与维护。
- 每个功能手动验收清单：桌面浏览器 + 手机浏览器各跑一遍。
- 发布前用 AI 做一次全项目静态检查（TypeScript strict + ESLint）。

## 8. 复刻校园的具体方法

1. **定比例尺**：在平面图上量出校门到主楼的实际距离，换算成瓦片数（如 1 米 ≈ 1.5 瓦片）。
2. **Blockout**：Tiled 里只用色块和道路，按平面图铺出 6 个区域和连接道路，先走通再美化。
3. **立面参考**：用学校 3D 地图截图确定建筑体量、层数、屋顶形状；用现场照片确定配色和窗户样式。
4. **地标优先级**：校门、主楼、图书馆、食堂、宿舍、操场看台做细；其余建筑简化为一两种通用楼型。
5. **校验**：按真实步行路线走一遍，误差控制在"感觉像"即可，不追求测绘级精度。
6. **版权**：只参考布局与外观特征，不直接提取学校 3D 地图的模型/贴图。
