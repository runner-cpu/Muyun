# SIMULATION · 牧云模拟内核

`client/src/sim/` 是一个不依赖 Phaser、不依赖 DOM 的纯 TypeScript 畜牧模拟内核。
所有随机性都来自注入的确定性 RNG，因此同一 seed 可以完整重放，也可以批量跑蒙特卡洛。

## 模块

| 文件 | 职责 |
|---|---|
| `types.ts` | `Animal` `PastureCell` `RunState` `Action` `EventCard` `Ending` |
| `rng.ts` | mulberry32 确定性随机 |
| `calendar.ts` | 13 周 → 四季映射 |
| `animal.ts` | 个体生长曲线、目标体重、体况评分（BCS 1–5） |
| `nutrition.ts` | 干物质采食量（牦牛 2.5% BW/日、藏羊 3.5% BW/日）、周需要量、采食率 |
| `pasture.ts` | 草场小区、承载力（羊单位）、放牧、休牧恢复、退化 |
| `reproduction.ts` | 配种资格（BCS ≥ 2.5）、受胎率、局末产犊 |
| `disease.ts` | 疫情风险（密度/季节/免疫）、传播、死亡与康复 |
| `economy.ts` | 活畜价格（体重/体况/季节）、草价、周成本、科技费用、结局判定 |
| `weather.ts` | 雪灾概率、天气抽取 |
| `events.ts` | 12 张事件卡与选项 |
| `run.ts` | 一局状态机：`createRun / applyAction / resolveEvent / endWeek / summarize` |

## 关键建模假设

- **一局 = 13 周**：春 1–3、夏 4–6、秋 7–9、冬 10–13。妊娠被抽象为「局末结算产犊」。
- **采食量**：干物质采食量按体重百分比**每日**计算，周需要量再乘 7、乘 1.1 的浪费系数。
- **草场**：4 个小区 × 2 公顷，初始 900 kg DM/ha；放牧最多取走 60% 现存量；
  休牧按季节恢复（夏 25%、春 18%、秋 8%、冬 2%）。
- **退化**：周需求超过现存量的 30% 的部分开始累积退化，系数 0.045。
- **繁殖**：BCS < 2.5 不发情；受胎率 `0.45 + (BCS - 2.5) × 0.25`，上限 0.9。
- **经济**：牦牛基准 7000 元、藏羊 1000 元；秋季溢价 8%，春季折价 8%；
  体况与体重共同调节价格；暴雪时草价翻倍。
- **科技**：项圈 180 元/头、免疫 12 元/头、草场监测 800 元/次。
  效果是**信息与风险**，不是数值加成。

## 蒙特卡洛结果

`npm run sim:monte` 跑 1000 局（4 档载畜量 × 250 局），输出：

- `reports/monte-carlo.csv`：每局的 ending / money / herdSize / degradation
- `reports/stocking-summary.csv`：分档汇总

参考策略：每周放牧最肥的小区、春秋配种、草料低于 500 kg 时割草、
秋季卖 2 头成年畜、事件总选第一项。

| 载畜量 | 平均收入 | 收入中位数 | 平均退化 | 生态崩溃率 |
|---:|---:|---:|---:|---:|
| 0.6× | 55,736 | 55,196 | 0.194 | 0% |
| 0.8× | 55,958 | 55,496 | 0.368 | 0% |
| 1.0× | 10,375 | 10,220 | 0.649 | 0% |
| 1.2× | 10,503 | 10,560 | 0.758 | **100%** |

**结论**：在 0.8× 与 1.0× 之间存在一个陡峭的阈值——收入跌到五分之一，
草场退化翻倍；到 1.2× 时所有模拟局都以生态崩溃收场。
这条阈值曲线就是「草畜平衡」政策要处理的核心矛盾，也是作品答辩时的主论据。

> 注意：这是**参考策略**的结果，不是最优策略。真人玩家可以通过提前买草、
> 主动减载、免疫和监测把可承受的载畜量往上推——这正是游戏要教的东西。
