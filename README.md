# 牧云 · Muyun: Highland Ranch

以高原草畜平衡为主题的像素牧场决策游戏。观察冬草、连续休牧和牦牛/藏羊负载，比较不同经营偏好，亲自安排经营，再用真实结算与同条件实验回顾取舍。

可以经营跨越四季的十三周完整局，也可以直接进入固定四周越冬挑战。模拟内核独立于 Phaser，经营界面、策略试算和批量实验复用同一套规则。

[在线体验 · GitHub Pages](https://runner-cpu.github.io/Muyun/)

```bash

```

打开 `http://localhost:5173`。生产构建与预览：

```bash
npm run preview
```

## 怎么玩

1. 在标题选择完整经营或「四周越冬挑战」。挑战从第 10 周开始，固定 seed 20261030，照料 12 头牦牛和 18 只羊，完成四次周结算。
2. 首次进入牧场会展示三步简易引导，可以跳过或关闭，也可从「帮助」重看；引导不执行经营或消耗资源。展开「本周安排」进入概览，先看本季使命和缺草、患病、现金耗尽风险，再核对需草与维护费。需要时展开「三周储备、策略试算与高原手记」，查看后续库存/现金压力、全局成果距离及季节、休牧和畜群负载解释。
3. 每周基础 3 个行动点。展开「经营工具」，通过畜群、草场、集市、科技安排轮牧、割草、补草、治疗或适度减载；雇工从下一周提高上限，最多 5 点。科技的效果与监测表按需展开，购置费、维护费和行动点仍直接可见。
4. 开通草场监测后，进入「本周策略试算」运行三种偏好对照。先看「不再行动」基线，再比较均衡经营、草场优先、资产优先的原始指标与变化；展开行动顺序、逐步效果和分项贡献，导出可复算的本周实验单，再回到经营面板亲自执行。试算本身不花行动、不改变存档。
5. 展开「周结算」并点击「结束本周」，确认饲草和费用，阅读实际变化并处理下一周事件。完整经营在第 13 周结算结束；挑战恰好结算四次。
6. 局末查看经营、生态和动物健康三维成果、季末使命与逐周记录，运行同条件策略对照，区分引擎完成、成果达标和保留存栏，再导出本局 JSON 或用相同条件再试。

当前规则为 `decision-v2`：放牧补充本周采食，割草增加干草库存；每个小区每周合计只能放牧或割草一次，两者都会中断连续休牧，只有当周未使用区在周末自然恢复。剩余行动点不结转。最高成果还要求现金为正并保留至少一半记录起点的羊单位，卖空畜群不能取得最高成果。五分钟左右的演示编排与完整步骤见 [演示指南](docs/DEMO.md)，实际时长需现场排练。

事件会列出即时变化与不可用原因；只有常规选项全部不可执行时才出现资源不足兜底，仍需承担在栏 BCS −0.2、草场退化 +0.02 的有界代价。

## 信息科技与策略实验

- **虚拟项圈**：展示已佩戴个体的 BCS、真实记录趋势和关注项；无历史时显示「首次记录」。每头购置 180 元，按存活佩戴个体每周维护 3 元。
- **草场监测**：购置 800 元、消耗 1 行动点，每周维护 30 元，解锁各区放牧/休牧预测和本周策略试算。
- **全群免疫**：按存栏每头购置 12 元，每周维护 40 元，降低游戏中的疫情传入概率。
- **高原手记**：从当前状态解释冬草储备、同批休牧地的冬夏增草对照、利用对连续休牧的打断，以及羊单位与体重需草两种口径。干草库存不会降低游戏暴雪概率；手记是游戏模型解释。
- **三周储备账**：固定当前畜群、体重和设备，未来不安排放牧、收割或买卖，列出库存缺口、按季节补足草费和持续费用；当周已放牧只抵扣当周。它是压力参照，不是未来预测或可自动执行的补给计划。全局保留目标固定参考本局真实记录起点。
- **三种偏好**：规划器 `beam-profile-v2` 对同一起点分别执行宽度 24、最多 5 层、每节点最多 16 候选（每组最多扩展 1552 节点）的受约束 beam search，补齐整公斤小缺口和保留维护现金的部分购草候选。原始指标相对同一「不再行动」基线比较，动作明细区分行动即刻变化与「若此时结算」；相同行动如实标明，不用不同权重的总分排名。
- **本周实验单**：独立导出当前输入、版本、权重、约束、基线、参考动作和假设结果，可用命令行复算。预测复用饲喂、生长、休牧与费用阶段，不包含未来随机天气、事件或疫病。
- **完局对照**：玩家记录、固定贪心、每周默认均衡搜索从同一真实起点和 seed 比较；自动策略采用相同可支付事件规则，搜索承担实际设备成本。

挑战的 6000 元是监测和十个项圈安装后的可用现金，不再扣购置费；四周仍分别扣除人工与维护。完整经营需自行决定是否购置设备。

搜索有限，不保证最优或全局帕累托前沿。当前 `decision-v2` / `beam-profile-v2` 公开 seed 实验仍使用默认均衡搜索：完整局贪心失败 30/30、搜索 0/30，挑战贪心失败 1/30、搜索 0/30；但四组最高成果达标均为 0/30，搜索全部只是「维持经营」，完整局还有 6/30 未保留开局一半羊单位。挑战搜索生态分较高，经营分和净资产却低于贪心。三偏好本周试算不等于三套完局策略已经通过批量对照，零失败率也不等于达标率。模型参数、评价公式和完整结果见 [模拟与基准](docs/SIMULATION.md)。尚无真实牧场收益或教学效果验证，没有真实 IoT 接入或疾病诊断。

## 操作与存档

牧场界面分为牧场状态、本周安排、经营工具、周结算和帮助五个可收起栏。首次默认全部收起，一次只展开一栏；收起标题仍显示周次、本周风险与行动点摘要。当前浏览器会独立记住展开状态，不影响完整经营与挑战的存档。帮助中集中提供重看简易引导、玩法说明、高原手记和设置。

| 操作 | 桌面 | 手机 |
|---|---|---|
| 展开或收起界面栏 | 点击标题，或聚焦标题后按回车 / 空格 | 点击标题 |
| 打开经营面板 | 展开经营工具并点击入口，或 `1` 畜群 / `2` 草场 / `3` 集市 / `4` 科技 | 展开经营工具并点击四项入口 |
| 在牧场走动 | `WASD` / 方向键 | 左下虚拟摇杆 |
| 靠近设施互动 | `E` / 空格 | 右下互动按钮 |
| 关闭面板或打开设置 | `Esc` | 关闭按钮或设置入口 |

手机建议横屏；菜单提供晨光、暮色与跟随系统外观。有效经营行动、事件选择和周结算后自动保存。

概览新增默认收起的本周真实行动记录，可核对已执行操作和未利用草区，再直接进入周结算确认。集市查看储备账后会保留购草输入、筛选与页码；策略试算往返保留同一状态的结果和所选偏好，实际经营状态改变后自动失效。

周试算与局末策略对照在后台 Worker 中计算，可以取消，关闭面板也会停止计算；失败或超过 60 秒可重试，不修改真实经营记录。长面板滚动时保留标题与关闭入口。必需素材加载失败时提供重新加载按钮；损坏当前版本存档会明确提示并保留原数据，已有完整局重开需确认。

保持存档 schema v2，与模拟规则 `decision-v2` 分开编号。完整局存档键为 `muyun-save`，挑战为 `muyun-save-winter`；标题可以分别继续，退出或重开一个模式保留另一个模式的进度。旧档保留可用经营状态；缺少记录或旧模拟版本从本次续玩状态重建起点与基线，保留当前周已知小区利用，不补造旧周次，也不把旧规则轨迹按 v2 重放；没有可玩历史的已结束旧档只能导出标明来源的状态快照，不能生成历史对照。

存档保存在当前浏览器，无账号同步；清除浏览器数据会丢失本地进度。局末 JSON 含版本、场景、真实起点、行动与周轨迹，供技术重放与核验；试算页的「本周实验单」另存假设输入与预测，两者不混入同一历史。当前没有界面导入存档入口。

## 验证与实验

2026-11-01 综合检查覆盖 38 个角度，实施记录、剩余模型问题和验证边界见 [综合分析](output/review/2026-11-01-comprehensive-analysis.md)。本轮 330 项单元/逻辑测试通过，并在真实 Chromium 中完成 13 组浏览器检查；这不替代移动真机、专业审查或教学效果研究。

```bash
cd client
npx tsc --noEmit
npm test
npm run build
npm run sim:strategies
```

策略脚本在完整局和四周挑战分别比较 30 个公开 seed，各输出两种策略的 CSV/JSON、汇总和失败案例。原载畜量实验仍可运行 `npm run sim:monte`；其结果中的 `money` 是期末现金，不能称为收入。`reports/` 是本机生成输出，不随仓库发布；方法和当前快照见 [SIMULATION.md](docs/SIMULATION.md)。测试通过不代表已完成手机真机、性能和浏览器兼容性验收。

在试算页下载本周实验单后，可从 `client` 复算，替换为实际文件路径：

```bash
npm run sim:verify-week -- "C:/Users/runner/Downloads/muyun-week-20261030-w10.json"
```

通过时输出 `valid: true`。校验器要求模拟与规划器版本一致，核对公开权重、约束和全部非耗时结果；它验证模型内复算一致性，不是文件来源认证，也不把假设方案写入真实记录。

前一轮从26个角度进行深审，新增三周储备与全局目标、补全小额购草候选，并修复清档隔离、重放校验与键盘输入。发现、实际改动和后续优先级见[深化分析](output/review/deep-refinement-analysis.md)，该轮测试、浏览器与导出复算证据见[深化验收](output/review/deep-refinement-acceptance.md)。

本轮增加五个 HUD 收纳栏、面板明细展开和三步简易引导，42 个测试文件、310 项测试及生产构建通过；桌面与横屏浏览器验收、实现边界见[收纳与引导验收](output/review/hud-disclosure-acceptance.md)。横屏使用浏览器视口模拟，尚未覆盖移动设备真机。

## 已知限制

- 参数、使命阈值和评分权重是游戏设计，专业知识依据、真人学习效果与难度仍待核对和试玩。
- 场景每种牲畜显示活体数 45% 向上取整、最多 18 头的真实 ID 样本；点击精灵和畜群耳标查看同一档案。样本坐标是展示槽位，不表示该头动物实际所属放牧区或真实路径；准确存栏以 HUD 与完整畜群表为准。
- 旧档未记录的行动、死亡原因和未决事件无法推断；恢复与对照只依据明确记录。
- 搜索只看当前周可见状态与有限候选，不证明全局最优，也不预测真实牧场。
- 固定冬价的干草估值、单周目标与季末使命存在取舍偏差，可能诱导过度储草；本周安全与整局达标分开。饲喂、人手事件等模型口径待独立规则版本验证，详见 [玩法深审](output/review/deep-gameplay-audit.md)。
- 公网发布、iOS Safari、Android Chrome 和真机触屏/性能需独立验收。

## 部署

Vite 使用 `base: './'`，支持静态部署：

- Vercel：Root Directory 为 `client`，Build Command 为 `npm run build`，Output 为 `dist`。
- Netlify：根目录 `netlify.toml` 已配置 `base = "client"`。
- GitHub Pages：`.github/workflows/pages.yml` 提供构建部署流程。
